# 桌面详情

桌面详情用于查看和修改单台虚拟机的完整配置，是日常运维最核心的页面之一。


## 页面整体

本页面通常分成两大区域：

- 顶部操作栏：负责快速运维动作
- 下方标签页：负责看和改具体配置

## 顶部操作栏

顶部操作包括：

- `远程连接`
- `电源`
- `运维`
- `编辑`

## 远程连接

1. 进入目标虚拟机详情。
2. 点击`远程连接`。
3. 系统会打开VNC页面。

## 电源操作

1. 点击`电源`。
2. 选择开机、关机、强制关机、重启、强制重启或恢复。
3. 提交后等待状态刷新。

### 电源操作

| 操作 | 适用场景 | 说明 |
| --- | --- | --- |
| 开机 | 虚拟机当前已关机 | 正常启动 |
| 关机 | 系统仍可正常响应 | 更安全的正常关机 |
| 强制关机 | 普通关机无响应 | 类似直接断电，谨慎使用 |
| 重启 | 需要重启系统生效 | 正常重启 |
| 强制重启 | 系统卡死 | 风险高于正常重启 |
| 恢复 | 从暂停或挂起恢复 | 依赖当前状态 |

## `运维`菜单

点击`运维`后，常见会包含：

- 迁移
- 备份
- 快照
- 克隆


## 运维 -> 备份

### 操作步骤

1. 点击`运维 -> 备份`。
2. 选择备份格式。
3. 选择备份存储。
4. 选择备份模式。
5. 填写备注。
6. 提交执行。
7. 完成后进入`虚拟机管理 -> 备份管理`查看结果。

### 备份字段说明

| 字段 | 是否必填 | 含义 | 推荐值 / 什么时候这样选 | 示例 | 注意事项 |
| --- | --- | --- | --- | --- | --- |
| 备份格式 | 是 | 备份压缩格式 | 一般优先 `zstd` | `zstd` | 会影响速度与体积 |
| 备份存储 | 是 | 备份文件保存位置 | 选容量充足的备份存储 | `backup-nfs` | 看剩余空间 |
| 备份模式 | 是 | 备份时对虚拟机的处理方式 | 在线业务优先 `snapshot` | `snapshot` | 模式不同，中断程度不同 |
| 备注 | 否，但建议填写 | 后续检索和追溯说明 | `2026-03-11 升级前备份` | `test` 这类备注不建议用 |

### 备份格式有什么区别

- `gzip`：压缩效果好，速度相对一般。
- `lzo`：速度快，适合赶时间。
- `zstd`：速度和压缩率比较均衡，通常最推荐。

### 备份模式有什么区别

- `snapshot`：业务影响最小，优先推荐在线业务使用。
- `suspend`：会短暂停顿，适合能接受短暂中断的场景。
- `stop`：会停机，适合维护窗口或测试环境。

### 备注规范

建议至少包含：

- 时间
- 操作原因
- 操作前场景

推荐示例：

- `2026-03-11 显卡驱动升级前`
- `考试封版备份`
- `财务环境补丁前`

## 运维 -> 快照

### 操作步骤

1. 点击`运维 -> 快照`。
2. 输入快照名称。
3. 如界面提供该选项，可决定是否包含内存状态。
4. 点击确认提交。
5. 等待任务完成。
6. 在快照列表中查看新快照。

### 快照名称怎么写

建议采用“日期 + 场景”的方式：

- `2026-03-11_before_patch`
- `exam_baseline`
- `office_clean_state`

不建议：

- `1`
- `test`
- `aaa`

### 做快照时机

适合：

- 打补丁前
- 改驱动前
- 测试软件安装前

## 运维 -> 克隆

### 操作步骤

1. 点击`运维 -> 克隆`。
2. 选择目标节点。
3. 选择快照。
4. 选择克隆方式。
5. 填写克隆数量。
6. 填写起始编号。
7. 填写命名规则。
8. 如界面支持，再决定是否自动加入桌面池。
9. 提交后等待克隆完成。
10. 回到`桌面管理`检查新桌面。

### 克隆时最关键的字段怎么理解

| 字段 | 含义 | 推荐值 / 什么时候这样选 | 示例 | 注意事项 |
| --- | --- | --- | --- | --- |
| 目标节点 | 新克隆虚拟机要落到哪台宿主机 | 选资源更空闲的节点 | `node2` | 先看目标节点资源是否足够 |
| 克隆方式 | 链接克隆或非链接克隆 | 批量发桌面优先考虑链接克隆 | `链接克隆` | 不同方式对存储和模板依赖不同 |
| 选择快照 | 根据VM的快照来克隆 | 只克隆虚拟机的某个状态 | `wps已安装` | 如果没有快照则可以不选 |
| 克隆数量 | 一次复制多少台 | 需要大批量部署 | `10` | 大批量可能会阻塞io，需要等待 |
| 起始编号 | 新虚拟机 VMID 起始值 | 选连续、未占用编号段 | `300` | 必须避免冲突 |
| 命名规则 | 批量生成的桌面名称规则 | 用统一前缀最好维护 | `ClassA-Desk{n}` | 避免名称杂乱，最后会是 ClassA-Desk-1，ClassA-Desk-2|

### 链接克隆和非链接克隆的区别

#### 链接克隆

- 优点：快、占用空间少。
- 适合：教学、培训、批量发桌面。
- 风险：更依赖模板和底层存储条件。

#### 非链接克隆

- 优点：每台桌面更独立。
- 适合：长期使用、个人数据保留较多的场景。
- 风险：速度更慢，占用存储更多。

## 运维 -> 迁移

### 操作步骤

1. 点击`运维 -> 迁移`。
2. 选择目标节点。
3. 根据业务情况确认是否在业务低峰执行。
4. 提交任务。
5. 到任务或日志中查看结果。
6. 完成后确认虚拟机节点已变化。

### 什么时候需要迁移

- 原节点资源紧张
- 节点维护前腾挪业务
- 某节点硬件异常需转移桌面
- 做资源均衡

## 概览页

- 虚拟机编号和名称
- 当前所属节点
- 当前运行状态
- CPU / 内存 / 磁盘 / 网络使用情况
- 虚拟机内部 IP 信息 （如果看不到，则证明虚拟机未正确配置）

### 虚拟机内部ip 信息无法看到

- 虚拟机代理未安装（请安装qemu-ga）
- 虚拟机代理未启动（确保虚拟机内部驱动已全部安装）
- 当前系统不支持或通信异常

## 计算资源页

计算资源页通常用于修改：

- CPU 数量
- 内存大小
- CPU 类型
- 内存回收相关项
- 部分直通设备显示

### 修改 CPU / 内存步骤

1. 打开`计算资源`标签页。
2. 找到 CPU 和内存对应项。
3. 修改目标值。
4. 点击保存。
5. 如果系统提示必须关机，则先关机再改。

### CPU 型号

建议：

- 没有特殊兼容性要求时，优先用平台当前稳定默认值。
- 只有在迁移兼容、老系统兼容或特殊软件要求时才改。

### 内存回收

宿主机在资源紧张时，尝试从虚拟机回收部分可回收内存。

适合：

- 高密度桌面环境
- 对资源利用率要求高的环境

不建议开启：

- 对实时性能敏感的桌面
- 图形负载较重且内存波动大的场景

## 存储资源页

这里通常可以管理：

- 系统磁盘和数据磁盘
- 光驱
- EFI 磁盘
- 未使用磁盘
- 启动顺序


### 添加磁盘步骤

1. 打开`存储资源`标签页。
2. 点击`添加磁盘`。
3. 选择总线类型。
4. 选择编号。
5. 选择存储池。
6. 输入磁盘大小。
7. 提交保存。

### 磁盘字段说明

| 字段 | 含义 | 推荐值 / 设置规范 | 示例 | 注意事项 |
| --- | --- | --- | --- | --- |
| 总线类型 | 磁盘接入方式 | 普通桌面常优先 `scsi` | `scsi` | 老系统兼容时可能要用 `ide` |
| 总线编号 | 当前类型下设备编号 | 选未占用编号 | `scsi0` | 不能和现有编号冲突 |
| 存储池 | 磁盘放置位置 | 选空间够、性能匹配的存储 | `local-lvm` | 系统盘和数据盘可按性能分层 |
| 磁盘大小 | 新增磁盘容量 | 先按业务真实需要设置 | `100GB` | 不要只看当前，考虑未来增长 |

### 总线类型

- `scsi`：半虚拟化，通用推荐，性能好。
- `virtio`：性能更好，但要看系统兼容性。
- `sata`：全虚拟化的磁盘模式，性能差，但免驱
- `ide`：更偏旧系统兼容。仅支持x86
- `nvme`：模拟为nvme，免驱，但通用性不强。

### 设置为启动磁盘

将这个磁盘作为第一启动的磁盘

## 网络资源页

网络页主要用于：

- 查看虚拟网卡
- 修改桥接、VLAN、带宽等配置

## PCIe / USB / 设备直通

如果详情页中有 PCIe 或其他设备页，通常用于给桌面直通显卡、USB 控制器或其他硬件设备。

针对直通显卡等PCIe设备直通，请在PXVIRT 后台完成
