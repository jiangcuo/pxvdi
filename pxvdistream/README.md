## 1　引言

### 1.1 云桌面的最后一公里

云桌面把算力留在数据中心，把画面送到用户面前。这条"最后一公里"由远程显示协议承载，它直接决定用户对整套系统的评价——画面是否流畅、操作是否即时、外设是否可用。

长期以来，这条路径由少数国外协议主导：Citrix 的 ICA/HDX、VMware 的 Blast Extreme 与 PCoIP、微软的 RDP。它们在 x86 服务器与国际主流 GPU 生态上经过长期打磨，功能完整、表现成熟。

国内厂商也陆续推出了各自的自研协议，如华为的 HDP、深信服的 SRAP 等，在本土市场已有多年积累。这些协议通常与各自的桌面云平台配套提供，服务于自家的产品体系。

### 1.2 信创环境带来的技术条件

当云桌面要部署在信创环境中时，会面对一套不同于传统 x86 环境的技术条件：

- **处理器架构多样**——龙芯、鲲鹏、飞腾、RISC-V 等架构的指令集与性能特征差异很大；
- **GPU 生态不同**——摩尔线程、励算、沐曦等国产 GPU 的编码能力与驱动接口，与国际主流 GPU 不在同一套体系内；
- **操作系统不同**——openEuler、麒麟、统信等国产发行版在显示、音频、输入子系统上与通用发行版存在差异，且 ABI 不一致。

这不是某一家厂商单独面对的问题，而是所有云桌面方案都要跨越的工程门槛——国内外厂商都在做适配，只是**覆盖的范围与深度各不相同**。

### 1.3 PxvdiStream 的定位

PxvdiStream 是梨儿方自研的云桌面串流协议。针对上述环境，我们着力解决两个问题：

**一、扩大适配覆盖面。** 处理器、GPU、操作系统、终端形态——覆盖范围越广，用户在选型与扩容时受到的限制越少。

**二、不与套餐绑定。** PxvdiStream 不需要成套采购：既可单独部署，也可与已有平台、已有桌面资源组合使用。

| | |
|---|---|
| **适配面广** | 从龙芯到 RISC-V，从国产 GPU 到纯软件编码，覆盖面更宽 |
| **终端齐全** | 浏览器、PC、手机、平板、瘦终端，全端接入 |
| **不捆绑** | 不与套餐绑定，可与已有环境自由组合 |

## 2　产品定位

### 2.1 产品定义

PxvdiStream 是一套**完整的云桌面串流协议**，包含服务端组件、客户端 SDK 与配套的虚拟显示驱动。它把虚拟机的桌面画面与声音实时送到用户终端，同时把用户的键鼠、触摸、剪切板、文件和本地磁盘反向送达虚拟机。

与常见的 VDI 方案不同，PxvdiStream **不绑定虚拟化平台**——桌面可以来自 VMware、Hyper-V、KVM，也可以来自物理机，连接方式不随底层虚拟化而改变。

它也**不绑定管理平台**。它既是 **PXVDI 云桌面平台的默认连接方式**（管理员在虚拟机中部署 PxvdiStream 组件后，用户即可通过任意 PXVDI 客户端连接该桌面），也可以脱离平台独立使用：服务端组件直接部署在目标主机上，客户端连接该主机即可。

### 2.2 能力概览

| 能力 | 说明 |
|---|---|
| **高清画面** | 支持 H.264 / H.265 编码，自动选择当前硬件最合适的编码方式 |
| **虚拟显示** | Windows 使用自研虚拟显示驱动；Linux 独立会话使用 XRDP 与 xorgxrdp，为无物理显示器的主机提供桌面 |
| **动态调屏** | 分辨率、刷新率、缩放比例可在会话中动态调整，无需重连 |
| **精准交互** | 键盘、鼠标、触摸、手势、文本输入，含组合键与锁键同步 |
| **外设与数据** | 剪切板、文件传输、本地磁盘、USB 设备、命令行终端 |
| **音频回放** | 服务端音频实时送达终端 |
| **全端接入** | 浏览器、Windows / Linux / macOS 桌面、Android / iOS 移动端、瘦终端 |

### 2.3 产品价值

**对最终用户：** 打开即用，操作响应及时，与本地桌面的体验差异小。浏览器可直接访问，无需安装任何客户端软件。

**对 IT 管理员：** 一个组件覆盖全部桌面场景，不需要为不同硬件准备不同方案。能力开关集中管控，可按用户、按桌面下发策略。

**对集成商：** 协议为自有实现，可按项目需要定制。全栈信创适配，满足项目对国产化的要求。

## 3　架构总览

### 3.1 组件构成

PxvdiStream 由三部分组成：

```
┌─────────────────────────────────────────────┐
│                 用户终端                      │
│   浏览器 │ 桌面客户端 │ 移动客户端 │ 瘦终端      │
└───────────────────┬─────────────────────────┘
                    │  加密连接
┌───────────────────▼─────────────────────────┐
│              PXVDI 云桌面平台                 │
│   总控平台 · 用户认证 · 桌面调度 · 策略下发      │
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│              目标虚拟机                       │
│   PxvdiStream 服务端组件                      │
│   · 屏幕捕获    · 虚拟显示驱动                 │
│   · 音视频编码   · 外设重定向                  │
└─────────────────────────────────────────────┘
```

**服务端组件**部署在虚拟机内，负责画面捕获、编码、外设接入与数据回传。

**虚拟显示驱动**为无物理显示器或多显卡的虚拟机、以及物理机提供虚拟屏幕，使操作系统与应用程序能够正常渲染桌面。

**客户端**以多种形态提供，共用同一套协议，因此各端体验一致、功能对齐。

### 3.2 两条传输路径

PxvdiStream 支持两种连接方式，由网络环境自动选择：

- **实时媒体通道**——面向视频与音频，采用低延迟 RTC 传输，具备网络穿透能力，适用于互联网、跨区域、NAT 等复杂网络环境。
- **统一数据通道**——在单一加密连接上承载全部控制类数据，适用于内网、专线等稳定环境。

两条路径对上层能力完全等价：无论走哪条，可用功能一致。

### 3.3 自研显示链路

在 Windows 桌面场景下，PxvdiStream 使用**自研的虚拟显示驱动**，配合从显卡直接取帧的编码路径——画面从产生到编码**全程留在显卡内部，不经由系统内存中转**。

**零拷贝带来的收益。**

| | |
|---|---|
| **CPU 占用低** | 编码不需要 CPU 搬运画面数据，处理器资源留给用户的应用程序 |
| **延迟更低** | 省去数据在显存与内存之间的往返，缩短了从操作到显示的路径 |
| **高分辨率收益更大** | 4K 及以上分辨率数据量大，减少内存往返带来的改善更为显著 |

**适用范围。** 这条路径需要机器具备可用的硬件编码能力。在无 GPU 或仅能软件编码的环境下，画面需回读内存，此时 PxvdiStream 依靠优化的软件编码路径保证可用性。

### 3.4 设计取向

PxvdiStream 在几个关键取舍上选择了体验优先：

- **低延迟优先于压缩率**——多占用少量带宽，换取操作的即时响应；
- **自适应优先于固定参数**——码率、分辨率、编码方式随环境调整，无需用户手工配置；
- **端到端自主**——关键环节自有实现，问题可定位到根因，不必等待第三方厂商响应。

## 4　核心能力

### 4.1 显示与画面

**虚拟显示。** Windows 桌面使用自研虚拟显示驱动；Linux 独立会话通过 XRDP 与 xorgxrdp 提供 X11 桌面。两者都可用于没有接入物理显示器的主机，部署方法见[安装与配置 Agent](./install.md)。

**高效编码。** 在具备硬件编码能力的机器上，画面从显卡内部直接进入编码器，不经由内存往返，显著降低 CPU 占用与传输延迟。详见 [3.3 自研显示链路](#_3-3-自研显示链路)。

**动态调屏。** 用户可在会话进行中调整分辨率、刷新率与缩放比例。终端窗口尺寸变化时，桌面分辨率可随之匹配，避免画面拉伸或黑边。

**缩放档位。** 支持 100%～300% 的缩放档位，适配高分屏与视力辅助场景。

**高帧率。** 虚拟显示器支持 30～240 FPS，适配主流高刷新率显示器。

### 4.2 交互

**键鼠操作。** 完整的键盘与鼠标支持，包含组合键（Ctrl+Alt+Del、Alt+Tab、Win 等）与锁键状态同步（Caps Lock / Num Lock）。

**触摸与手势。** 移动端与触摸屏终端支持点击、双击、长按、滑动、缩放、旋转等手势，在平板上操作云桌面接近原生体验。

**文本输入。** 支持直接向远端输入文本，适配中文等非拉丁语系场景。

### 4.3 外设与数据

**剪切板。** 支持文本、HTML、RTF、图片与文件的剪切板互通，方向与容量可由管理员策略控制——例如限定为单向传输、限制文件体积、禁用图片。

**文件传输。** 内置文件管理器，可在终端与虚拟机之间上传、下载文件，支持大文件分块续传与完整性校验。

**本地磁盘。** 把用户终端的本地目录映射为虚拟机中的磁盘，应用程序可直接读写本地文件，无需预先上传。支持只读挂载与文件类型过滤。

**USB 设备重定向。** 把用户终端上的 USB 设备接入虚拟机，供桌面内的应用程序直接使用，适用于 U 盾、加密狗、专用读卡器等场景。设备的接入与移除在会话中实时生效，无需重启桌面。

> 当前该能力面向 Windows 桌面提供，并需由虚拟机内的 PxvdiStream 组件建立受信任会话；非 Windows 宿主暂不支持。

### 4.4 音频

服务端音频实时送达终端播放，适用于视频播放、语音提示等场景。音量与码率可调。

### 4.5 连接与接入

**全端客户端。** 浏览器、桌面端、移动端、瘦终端共用同一协议，功能与体验保持一致。

**网络自适应。** 支持 STUN/TURN 穿透，在 NAT 与防火墙环境下无需调整网络配置即可连接。

**WebSocket 通道。** 支持纯 WebSocket 传输，可用于网络受限或隔离环境。

**会话管理。** 支持会话建立、断开重连与多用户并发。


### 4.6 会话模式

**远程控制。** 直接作为远程控制连接远程电脑。
**远程会话。** 在远程电脑上，创建会话，通过远程会话方法进行访问。支持多用户共享。

### 4.7 平台与部署

**多协议共存。** PxvdiStream 与 RDP、SPICE、VMware Horizon、Moonlight 等协议在同一平台内共存，管理员可按场景为不同用户、不同桌面配置不同连接方式。

**统一策略下发。** 能力开关（剪切板方向、磁盘映射、文件类型限制等）由总控平台统一下发，无需逐台配置。

**极简安装。** Linux 下为单个 deb / rpm 包，安装后即可使用。

**多架构服务端。** 管理平台使用 Rust 编写、musl 构建，支持 LoongArch64、AMD64、ARM64、RISC-V 64 四种架构的 Linux。针对 LoongArch64 额外支持旧世界（ABI 1.0）。

## 5　安全

### 5.1 传输加密

PxvdiStream 的全部通信均经过加密，**不存在明文传输环节**：

| 数据类型 | 加密方式 |
|---|---|
| **信令与控制数据** | TLS，覆盖连接建立、身份认证、策略下发与各类控制指令 |
| **音视频与输入数据** | SRTP，媒体流在传输全程保持加密 |

两种加密方式分别对应两条传输路径，共同覆盖会话的全部数据流向。

### 5.2 身份认证

支持三种认证方式，由部署环境决定：

| 认证方式 | 说明 |
|---|---|
| **平台统一认证** | 由 PXVDI 总控平台完成用户认证，与平台内的资源、策略模型一致 |
| **域认证** | 接入域环境，使用域账户登录 |
| **本地账户** | 使用远程系统自身的账户密码认证，适用于独立部署 |

### 5.3 权限管理

权限由总控平台统一管理。用户可访问哪些桌面、可使用哪些能力，均通过策略下发，**无需逐台配置**。策略可精确到用户与桌面两个粒度。

### 5.4 外设与数据管控

剪切板、磁盘映射、USB 重定向等数据通道均可通过策略按需开启或关闭。

对数据管控要求严格的场景，可关闭全部重定向通道——此时桌面数据仅以画面形式呈现，终端不落地任何业务数据。

## 6　典型应用场景

### 6.1 政务与金融

**信创合规。** 要求从处理器、操作系统到应用形成全国产化链路。PxvdiStream 覆盖龙芯、鲲鹏、飞腾等国产处理器与主流国产操作系统，可构成端到端国产化方案，详见第 8 章。

**数据不出内网。** 业务数据须留在数据中心，终端不留存。PxvdiStream 传输的只有画面与操作指令，终端不落地业务数据；配合关闭外设重定向策略，可进一步收紧数据出口。

**外设可用。** 银行 U 盾、专用读卡器等设备需要接入桌面。PxvdiStream 支持 USB 设备重定向，终端上的设备可直接接入桌面内使用，无需为国产化改造放弃既有外设。

### 6.2 教育

**机房高并发。** 上课时段大量学生集中登录，对服务端的并发调度能力提出要求。

**存量老机器可用。** 教室与机房的机器多无独立显卡。PxvdiStream 的软件编码路径可在无 GPU 的虚拟机上提供可用桌面，无需为老旧设备单独采购硬件。

**统一运维。** 镜像与策略集中管理，教师机与学生机可按策略下发不同权限，减少机房维护工作量。

### 6.3 医疗

**影像调阅。** 医学影像对画面细节要求高，需要在高分辨率下清晰呈现。PxvdiStream 采用硬件编码，可保证影像的锐度与灰阶层次。

**终端形态多样。** 诊室工作站、护士站、移动查房设备各不相同。PxvdiStream 客户端覆盖桌面应用、浏览器与移动设备，同一套桌面可在不同终端上访问。

### 6.4 设计与制造

**GPU 工作站共享。** 三维设计与仿真依赖专业显卡，而一人一台工作站的成本较高。PxvdiStream 支持多用户共享同一台高性能工作站，每个用户获得各自独立的会话，互不干扰。

**终端无需高性能显卡。** 显卡集中在服务端，画面经硬件编码下发，终端只需具备解码能力——瘦终端、笔记本乃至移动设备均可获得工作站级的设计体验。

## 7　产品关系

### 7.1 在 PXVDI 平台中的位置

PXVDI 平台提供虚拟机管理、用户认证、桌面调度、策略下发等能力。PxvdiStream 是平台**默认开启**的连接方式——虚拟机装好 PxvdiStream 组件后，用户在平台上点击桌面即可连接。

平台的资源、用户、策略模型对 PxvdiStream 适用。部署时在桌面端[安装 Agent](./install.md)，再按[桌面部署与接入](../zong-kong-mo-shi/vm.md)完成资源关联与授权。

### 7.2 与其他连接方式的关系

PXVDI 支持多种连接协议，管理员可按用户、按场景自由选择：

| 连接方式 | 适用场景 |
|---|---|
| **PxvdiStream** | 默认。通用办公、图形设计、国产化环境 |
| RDP | 文字办公、Win7 兼容场景 |
| SPICE | 测试与调试 |
| Moonlight | 游戏与高帧率场景 |

多协议共存的价值在于：**同一个平台可以纳管不同来源的桌面**——新建的、已有的、第三方的——而用户面对的始终是同一个入口。

### 7.3 与外部环境的集成

- **认证集成**：可对接 PXVDI 总控平台完成统一认证，也支持域环境
- **桌面纳管**：可直接接管已有的 VMware、Hyper-V、KVM 虚拟机与物理机
- **信创生态**：与国产处理器、GPU、操作系统形成端到端闭环

## 8　信创适配

### 8.1 适配矩阵

| 层次 | 已适配 |
|---|---|
| **处理器** | 龙芯、鲲鹏、飞腾、RISC-V、x86_64 |
| **GPU** | 摩尔线程、NVIDIA、AMD、Intel，以及无 GPU 纯软件路径 |
| **操作系统** | openEuler 及主流国产发行版、Ubuntu / Debian / RedHat 系、Windows  |
| **终端** | 通用 PC、移动设备、浏览器、Rockchip 嵌入式设备、鸿蒙设备 |

### 8.2 无 GPU 场景

在完全不配备 GPU 的虚拟机上，PxvdiStream 通过优化的软件编码路径仍可提供可用的桌面体验，适用于办公、教务等对图形性能要求不高的场景。

PxvdiStream 已针对信创 CPU 的 SIMD 指令集（如龙芯 LSX）完成适配，在 TLS 解密、图像格式转换与数据压缩等环节显著降低了 CPU 开销，明显改善国产处理器上的桌面流畅度。

这使得**同一套云桌面方案可以覆盖高低配混合的桌面池**，而不必为无 GPU 的机器另行准备方案。

### 8.3 自主可控

| | 说明 |
|---|---|
| **代码自主** | 协议栈为自有实现，不依赖第三方协议 |

## 9　已知限制

> 以下为截至本版本尚未覆盖的能力。列出这些边界，是为了让选型评估建立在准确预期之上，而非在部署后才发现缺口。

### 9.1 平台范围

| 能力 | 当前范围 |
|---|---|
| **虚拟显示驱动** | 仅 Windows 桌面。驱动提供 x86_64 与 ARM64 两个版本。Linux 桌面由 xorgxrdp 提供虚拟显示；**macOS 桌面须使用真实显示器**，无法为无头主机提供桌面。 |
| **多屏显示** | 不支持。每个会话仅提供一个虚拟屏幕，无法扩展为多个屏幕。 |
| **色彩还原** | 画面采用 4:2:0 色度采样（NV12），色彩信息量约为完整采样的四分之一。在色彩渐变、细密彩色文字等场景下还原有限，**不适用于对色彩准确性要求高的专业场景**。 |
| **USB 设备重定向** | 新版原生 USB 的桌面端实现面向 Windows，需要匹配的客户端、Agent 与驱动；SPICE 为另一种兼容方案。平台设备规则与限制统一见[USB 策略](../zong-kong-mo-shi/web/usb-policy.md)。 |

### 9.2 反馈

以上限制的解决进度随版本推进。若某项能力对您的场景构成阻塞，请通过技术支持渠道反馈，我们会评估优先级。
