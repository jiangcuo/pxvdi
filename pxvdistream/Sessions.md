# 会话模式

PXVDIStream 提供两种会话模式，区别在于**远程画面从哪里来**：

- **远程控制**——直接连接远程电脑的物理控制台，画面为物理屏幕或虚拟显示器。
- **远程会话**——在远程电脑上创建独立会话，画面来自该会话的虚拟桌面。

| 对比项 | 远程控制 | 远程会话 |
|---|---|---|
| **画面来源** | 物理控制台 | 该会话的虚拟桌面 |
| **物理屏幕** | 与远程画面完全一致 | 不受影响，可保持锁屏或显示其他内容 |
| **系统账户认证** | 不创建系统会话，连接仍需认证 | 需要远程系统的账户密码 |
| **多用户并发** | 不支持，控制台只有一份 | 支持，每个用户各自一个独立会话 |
| **会话隔离** | 无 | 完全隔离 |
| **适用系统** | Windows / Linux / macOS | Windows / Linux |

> macOS 仅支持远程控制，不支持远程会话。

“远程控制不需要系统账户密码”指不创建独立的操作系统会话，连接仍需通过平台或服务的认证。服务安装见[安装与配置 Agent](./install.md)；平台多用户授权见[共享会话桌面池](../zong-kong-mo-shi/web/shared-pool.md)。

## 远程控制

直接访问物理屏幕，操作体验与在本机前一致：物理屏幕上显示什么，远程端就显示什么；远程端的操作也会同步呈现在物理屏幕上。

**特点**

- 无需输入系统账户密码即可连接；
- 画面与物理屏幕**完全一致**，不存在独立的虚拟桌面；
- 同一时刻仅支持一路连接；
- 无人值守的机器可以正常连接。

**适用场景：** 运维排障、需要查看真实硬件状态的场合、单用户独占的机器。

## 远程会话

连接时 PXVDIStream 要求用户提供**远程系统上正确的账户密码**，验证通过后创建或恢复独立会话，用户的桌面在这个会话中呈现。

Linux 标准部署使用 XRDP：启用 `rdsh=true` 后，由本机 `xrdp-sesman` 完成系统用户认证，再由 xorgxrdp 提供该用户的 X11 会话。客户端通过 PXVDIStream 访问桌面；无头主机也按此方式部署。安装步骤和检查方法统一见[Linux 安装](./install.md#linux-安装)。断开连接后的会话保留与恢复由 XRDP 策略决定，断开连接与注销会话应分别处理。

**特点**

- 认证由远程操作系统完成，须提供正确的系统账户密码；
- 会话**彼此隔离**，也与物理控制台隔离——物理机可能处于锁屏状态，或正显示另一位用户的桌面；
- **支持多用户共享同一台机器**，每个用户登录自己的账户，各自进入独立会话，互不干扰；
- 每个会话拥有独立的虚拟显示器，分辨率、缩放比例、刷新率可**按会话单独设置**；
- 注销会话时，该会话内的应用程序随之结束。

**适用场景：** 多人共用一台高性能工作站、云桌面交付、需要与物理操作互不干扰的场合。

## 外设重定向

PXVDIStream 提供剪切板、磁盘与 USB 重定向能力，实际可用功能取决于桌面系统、客户端、Agent 和驱动支持。通过 PXVDI 平台接入时还受桌面池策略控制，其中共享会话桌面池强制关闭 USB。设备库、黑白名单及配置流程统一见[USB 策略](../zong-kong-mo-shi/web/usb-policy.md)。

**远程会话模式下的说明：** 由于会话之间相互隔离，USB 设备仅对所属会话可见。个别依赖控制台会话、或需要与物理设备独占绑定的设备可能无法在远程会话中使用；此类场景建议选用**远程控制**模式。

## 如何选择

| 需求 | 建议模式 |
|---|---|
| 多人共用一台机器、各自独立桌面 | 远程会话 |
| 需要与物理操作互不干扰 | 远程会话 |
| AD 域环境 | 远程会话 |
| 设备依赖控制台会话，或需独占访问 | 远程控制 |
| 运维排障、查看真实硬件状态 | 远程控制 |
| 无人值守、需长期保持连接 | 两者均可（远程会话不因物理锁屏而中断） |
